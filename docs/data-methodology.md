# 主队偏好推荐的数据方法

本文件说明 `dist/assets/club-match-data.json` 的来源、窗口、计算方式和使用边界。该数据用于按用户明确表达的观赛偏好寻找候选主队，不是人格测试、胜负预测或全球球队实力排名。

## 数据来源与使用限制

唯一数据提供方为 [Football-Data.co.uk](https://football-data.co.uk/data.php)。读取其公开 CSV，保留每份原始文件的 URL、下载时间、字节数和 SHA-256。欧洲采用 `mmz4281/<赛季代码>/<联赛代码>.csv`；南美采用 [ARG.csv](https://www.football-data.co.uk/new/ARG.csv) 与 [BRA.csv](https://www.football-data.co.uk/new/BRA.csv)。全部 47 个具体地址和原始文件指纹见 JSON 的 `metadata.sources`，不依赖搜索结果或第三方转载。

来源页面声明数据目标用途为私人个人使用，而不是通过自动化机器人、抓取或 AI 进行的商业／数据训练产品。这里**不主张数据具有开放数据许可，也不授予新的再分发权利**。本项目当前由父任务核实为仅所有者可访问的私人个人展示，匹配是透明的算术规则，不进行模型训练。这不等于获得未来公开或商业化许可；若改变访问范围、商业化、批量再发布或用于数据训练，应重新核实来源许可。来源用途说明于 2026-11-02 核对，摘要同时写入 `metadata.sourceUse`。

## 时间窗口与实际样本

- 欧洲：2020/21—2024/25 五个完整赛季。源目录依次为 `2021`、`2122`、`2223`、`2324`、`2425`；其中 `2021` 表示 **2020/21**，不是自然年 2021。
- 阿根廷、巴西：按比赛日期筛选 **2021-01-01 至 2025-12-31**，两端均包含。没有用 `Season` 列替代自然年筛选。
- 只接收日期有效、主客队非空、双方终场进球为非负整数的记录。缺少比分、日期不可解析、重复或冲突情况单独记录，不填造结果。

本次从 47 份源文件读取 27,138 行非空记录，排除南美窗口外的 7,299 行，得到 **19,839 场**不重复的窗口内赛事。日期无效、主客队缺失、比分缺失及重复记录均为 0。不能据此声称已独立核查所有真实比赛的完整性：这只是当前发布方文件中符合规则的记录数。

### 南美时间和赛制差异

自然年窗口会包含赛季标签不同的比赛。例如 BRA 源文件中有 112 场标签为 2020、实际日期落在 2021 年的比赛，按要求保留；所以弗拉门戈得到 **202 场**记录，而不是简单的 5 × 38 = 190。ARG 文件也有 26 场标签为 2020、实际日期落在 2021 年的记录。

阿根廷的联赛体系在这些年份改变过阶段和赛制，源文件可能列入联赛杯式或淘汰式的联赛冠军阶段。这里按原发布方 ARG 文件收录范围统计，不把它们伪装成五届完全相同的双循环联赛，也不把它们与欧陆联赛格式等同。博卡为 208 场，河床为 203 场；不同场次数不是人为补齐。每份南美来源的 `sourceSeasonRows` 和 `calendarYearRows` 可用于审计。

## 指标定义

令 `n` 为该俱乐部的比赛数，`GF` 为其进球数，`GA` 为其失球数。所有比率为 0—1 小数，展示时才转为百分比；数值保留六位小数，原始整数计数同时提供。

| JSON 字段 | 定义 | 可支持的直接观赛偏好 |
| --- | --- | --- |
| `goalsPerMatch` | `(GF + GA) / n` | 比赛中双方总进球较多或较少 |
| `scoringRate` | `GF / n` | 自己支持的球队进球频率 |
| `concedingRate` | `GA / n` | 历史失球频率 |
| `cleanSheetRate` | 失球为 0 的场次 / `n` | 历史零封频率 |
| `winRate` | 胜场 / `n` | 观察窗口内的获胜频率 |
| `homePointsRate` | 主场积分 / `(3 × 主场场次)` | 主场指定身份下的取分率 |
| `awayPointsRate` | 客场积分 / `(3 × 客场场次)` | 客场指定身份下的取分率 |
| `homeLift` | `homePointsRate - awayPointsRate` | 历史主客场取分差异 |

胜、平、负只由该队终场比分与对手比分比较得到，积分采用胜 3、平 1、负 0。双方比分相同就按平局统计，不根据淘汰赛晋级、点球大战或球迷叙述改写。`firstDate`、`lastDate` 是实际匹配记录的首末日期，不是俱乐部建队日期。

“主场”指来源 CSV 的主队身份，**不证明比赛一定在页面展示的球场举行**；中立场地、借用球场或临时迁场不会被自动识别。主客场差异不能直接解释为看台声浪、球迷热情或球场建筑造成的因果效果。

## 推荐边界

问题应直接询问用户希望看到的比赛特征，例如进球密度、获胜频率、进攻与少失球的取舍、对历史主客场差异的偏好。可以用这些明确偏好与上述历史频率进行透明匹配，但不能把“性格内向、勇敢、忠诚”等人格描述伪装成数据证实的球队关联。

不同联赛的对手强度、进球环境、赛制、赛程和样本窗口不同。本数据没有做联赛强度校正；凯尔特人、巴黎、曼城等的胜率不能当作相互交锋胜率或世界强弱顺序。历史窗口的频率也不预测未来赛季。没有球员、票价、球迷氛围、实时比赛或人格关联数据时，不生成这类“数据结论”。若前端使用分位数、距离或权重，这些是项目设定的匹配规则，必须与历史赛果事实区分。

欧洲不读取国内杯赛、欧洲赛事、友谊赛或国家队文件。阿根廷按提供方的联赛体系文件范围处理，保留前述阶段差异。没有加载赔率、庄家字段或博彩模型；发布 JSON 仅包含计数、频率、来源及其审计元数据。

## 重建与验证

在项目根目录执行，构建脚本仅使用 Python 标准库：

```text
python scripts/build-club-data.py
python scripts/build-club-data.py --offline
python scripts/build-club-data.py --refresh
```

首次构建下载缺失的源 CSV；默认复用 `research/football-data/` 缓存。`--offline` 完全不联网，缺少文件即失败；`--refresh` 重新下载。下载并发限制为 2，短暂服务错误最多重试 1 次并尊重有界的 `Retry-After`，不会轮换地址绕过限制。原始 CSV 存在被忽略的 research 目录，包含发布方原列，但**不进入站点部署产物**。

脚本保留每份源 CSV 的 SHA-256。`metadata.resultsSha256` 对所有标准化的窗口内比赛身份和比分计算，便于排查源文件修正。源提供方以后若修改历史 CSV，在线重建可能变化；要复现本次聚合，应使用与 JSON 中源指纹一致的缓存。`compiledAt` 会随运行时间改变，不能用整份 JSON 的字节相同作为聚合复现标准。
